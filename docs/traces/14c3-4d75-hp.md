# HP and `14c3:4d75` (FM350-GL): the transport is there, the key is not

HP's FM350 package, sp174156, binds `PCI\VEN_14C3&DEV_4D75` with subsystems
`103c:8914`, `103c:8a3a`, `103c:8c4a`, alongside Fibocom's own `1cf8:3500` and
`14c3:4d75`. This records a complete pass over its 18 binaries.

| Item | Value |
|---|---|
| SoftPaq | sp174156, sha256 `27c1937cc549a95d3f1cc8759205cc55611607f74e3718c97719ed05ffc6c58f` |
| Stack | MediaTek: `WwanNet.sys`, `WwanIHVDriver.dll`, `WwanComDriver.dll`, `WwanConfigurator.dll` |
| Also ships | `FwFlashDriver`, `FwFlashService.exe`, `FwManageDll.dll`, `flash.dll`, `FibocomGNSSDriver`, `FbWwanFilterService.exe`, `ThingsMatrixAgentService.exe`, `WirelessCCD.sys`, `devcon64.exe`, `UninstallTool.exe` |

## The unlock transport is advertised

`WwanConfigurator.dll` builds the MBIM device services response
(`DeviceServicesInfo::AddCIDtoService`, `AddServiceToHeader`). Its service table
at `0x180071ed8` is the standard MBIM list, and the Intel service sits in it:

| Index | Service |
|---|---|
| 2 | BASIC_CONNECT |
| 3 | SMS |
| 4 | USSD |
| 5 | STK |
| 6 | AUTH |
| 7 | MS_HOST_SHUTDOWN |
| 8 | MS_BASIC_CONNECT_EXTENSIONS |
| **13** | **`f85d46ef-ab26-4081-9868-4d183c0a3aec`, Intel Mutual Authentication (FCC lock)** |

So HP's own FM350 stack exposes CID 1 of that service. The unlock transport on
an HP FM350 is the Intel FCC lock MBIM service, the same one Dell's DW5931e uses
and the same one the `8086:7560` Dell method drives. It is **not** the AT
`+GTFCCLOCK` sequence Lenovo uses for this module, which is what upstream's
`14c3` script and this repo implement.

## Nothing in the package performs an unlock

Tested across all 18 binaries, the same way as for `8086:7560`:

| Test | Result |
|---|---|
| `FCCLOCK`, `fcc_lock`, `gtfcclock`, `FccUnlock`, `ModemAuth` strings | none |
| A 14 character model id of the `…FCCLOCK` form | none |
| SHA-256 constant table | only `ThingsMatrixAgentService.exe`, an eSIM and telemetry agent that also carries OpenSSL, TLS and HMAC code |
| Windows crypto imports | only that agent |
| MIPC `SET_FCC_LOCK` | absent; unlike sp173756, this package has no `libWncT.dll` or `libmipc.dll` |
| Intel FCC service GUID | only `WwanConfigurator.dll`'s service table above |
| Installed services (`WwanNet.inf`) | `WwanNet.sys`, `WwanIHVDriver.dll`, `FbWwanFilterService.exe`. No authenticator |

The AT commands present are SAR and TAS (`AT+BODYSAREN`, `AT+GTTASCTRL`,
`AT+GTTASEN`, `AT+GTTASRULE`), GNSS (`AT+ELCS*`, `AT+XLCS*`), and identity or
firmware ones (`AT+CGSN`, `AT+ESBP`, `AT+EGCMD`, `AT+GTSHELL`). Nothing resembling
`at+gtfcclockgen`. `AT+GTRLK` and `AT+GTRLKVER` are read only queries in
`FwFlashService.exe`, alongside its `LockCarrierID` and `LockMode` handling,
which is carrier locking and firmware switching, not the FCC lock.

`UninstallTool.exe` and `uninstall_driver.ini` do still remove a service named
`WWAN ModemAuthenticator`, so HP's FM350 stack expects one to exist; this
package simply does not carry it.

## The candidate sequence for HP

Two independently established facts meet here:

- The transport, from this package: Intel FCC lock MBIM service, CID 1.
- The key, from [hp-wwanmodemauthenticator.md](hp-wwanmodemauthenticator.md):
  HP's `CHpFccLock::GetFccCode` returns `WNCHPCEFCCLOCK`, sha256 prefix
  `576f0ae0`, and the INF of the package carrying that binary also binds
  `PCI\VEN_14C3&DEV_4D75`.

So the sequence to try on an HP FM350 is the `8086:7560` Dell method with
`576f0ae0` in place of `bb23be7f`: query, set with `ResponsePresent = 0` for the
challenge, `sha256(challenge ‖ sha256("WNCHPCEFCCLOCK")[0..3])`, set with
`ResponsePresent = 1`.

This is a candidate, not a traced fact: no HP binary has been observed hashing
that id for this module. It needs a report from an HP FM350 owner before it goes
into a dispatcher as an HP method.

## What this means for the `14c3` dispatcher

Upstream's `14c3` script and `modules/14c3:4d75` here implement Lenovo's AT
sequence only, with Lenovo's key. Three OEMs ship this module and at least two
of them do not use that path:

| OEM | Transport | Model id |
|---|---|---|
| Lenovo | AT `+GTFCCLOCK` | `KHOIHGIUCCHHII`, `3df8c719` |
| Dell | Intel FCC lock MBIM | `DW5931EFCCLOCK`, `4909b5a4` |
| HP | Intel FCC lock MBIM, advertised here | `WNCHPCEFCCLOCK`, `576f0ae0`, candidate |

That makes `14c3:4d75` the same problem `8086:7560` solved, and the largest
remaining gap in [../COVERAGE.md](../COVERAGE.md).
